3. SECURITY

Implement Supabase Authentication.

Use Row Level Security (RLS).

Default behavior:

- Users can access their own records.
- Admin can access all records.
- Admin can grant additional permissions to specific users.
- Permissions must be checked both in the UI and database policies.

Never rely only on hidden UI buttons for security.

Fields:

- Borrower/debtor
- Principal amount
- Interest rate
- Interest type
- Number of months
- Start date
- Due date
- Monthly expected payment
- Notes
- Status

Support flexible interest calculations.

The app should calculate the expected monthly amount and total payable based on the selected interest settings.

IMPORTANT:

Do NOT automatically mark a month as paid.

The user manually chooses:

- Paid
- Unpaid
- Partially Paid

Create a monthly payment schedule using the "debt_monthly_payments" table.

Allow the user to record a payment manually.

10. OFFLINE MODE

The application must continue working without internet.

Use:

Room Database → Local Storage

When internet becomes available:

Room → Supabase synchronization

Support:

- Offline add
- Offline edit
- Offline delete
- Offline debt payment
- Offline history
- Automatic synchronization

Prevent duplicate records during synchronization.

Use UUIDs/client-generated IDs where appropriate.

Handle synchronization conflicts safely.

16. MVP PRIORITY

Focus first on a working MVP.

The most important requirements are:

Login → Dashboard → Income → Expenses → Debt Tracker → History → Offline Mode → Supabase Sync → User Permissions

Do not add unnecessary complexity until these features are working correctly.

Before generating the final code, verify that the Supabase SDK version, imports, authentication API, Postgrest API, and database/RLS syntax are compatible with the current project.

Generate complete, runnable Kotlin code rather than pseudocode.
